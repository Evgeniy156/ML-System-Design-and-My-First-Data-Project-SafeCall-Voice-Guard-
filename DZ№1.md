# 🛡️ ДЗ №1 — SafeCall Voice Guard

> **Курс:** Машинное обучение (ИТМО)  
> **Тема:** Детекция голосовых дипфейков в телефонных звонках  
> **Методология:** CRISP-DM  

---

## 1. Бизнес-анализ (Business Understanding)

### Описание проблемы и цена ошибки
Мошенники активно используют технологии клонирования голоса (voice deepfake) для корпоративных и частных атак. Ущерб измеряется миллионами долларов (например, кейс кражи $35 млн у банка в ОАЭ). Современные генеративные системы создают убедительный клон всего по 3 секундам аудио, что делает угрозу критичной для бизнеса и частных лиц. Обычный человек не способен отличить дипфейк от оригинала, особенно в стрессовой ситуации.

### Бизнес-цель проекта
Создать B2B-сервис **SafeCall Voice Guard**, который в реальном времени анализирует аудиофрагменты телефонного звонка и предупреждает пользователя о подделке голоса, снижая риски мошенничества.
**MVP (канал доставки):** FastAPI-сервис (корпоративный REST API) и SIP-прокси. Звонки анализируются "в разрыве" телефонной сети, без выхода аудио за защищенный периметр компании.

### Конкурентное преимущество
- **Текущие решения:** Либо жестко привязаны к сети конкретного оператора (МегаФон, Билайн), либо стоят десятки тысяч долларов (Pindrop, Nuance).
- **Ниша SafeCall:** Операторонезависимое, встраиваемое локальное решение для малого и среднего бизнеса. Главный приоритет — **полная приватность** записей переговоров.

### Оценка рынка
Рынок детекции дипфейков растет с CAGR ~28-42%. Потери бизнеса удваиваются ежегодно (в РФ рост атак в 2.3 раза за 2025 год). При средней стоимости инцидента в $500K, внедрение решения имеет колоссальный ROI.

## 1.1 Текущая ситуация (Assessing Current Solution)

### Оценка ресурсов и данных
- **Оборудование:** Имеющегося GPU (RTX 4070 8GB) достаточно для бейзлайна и локального fine-tuning.
- **Датасеты:** Используются открытые бенчмарки (ASVspoof 2019/2021, WaveFake, In-The-Wild, Golos, MUSAN для шумов).
- **Синтез RU-дипфейков:** Для устойчивости к атакам в РФ планируется генерация 5K–10K русскоязычных сэмплов с использованием реальных инструментов мошенников (Silero TTS, XTTS v2, RVC, ElevenLabs). Разнообразие синтезаторов критически повышает генерализацию детектора.

### Предобученные модели
- **Baseline:** AASIST (легковесная и быстрая архитектура).
- **Основная модель (Fine-tune):** XLSR-53 (wav2vec 2.0) — мультиязычный SSL-энкодер, отлично подходящий для русского языка.

### Ключевые риски
- **Деградация качества на реальном телефоне:** Телефонные кодеки (AMR-NB) обрезают высокие частоты, скрывая артефакты дипфейков. **Решение:** Обучение на аугментированных данных (эмуляция телефонного канала, добавление шумов).
- **Ложные срабатывания (False Positive):** Снижение за счет аккуратной настройки порога (trade-off) и скользящего окна предсказаний.

## 1.2 Решаемые задачи (Data Mining Goals)

### Постановка задачи
Бинарная классификация аудиофрагментов (чанков длительностью 3-5 сек, 16 kHz): определить класс **real** (настоящий голос) или **fake** (синтезированный).

### Стратегия чанкования
- **Размер и перекрытие:** Чанки по 3–5 секунд с 50% перекрытием. Оптимальная длина будет выбрана экспериментально по максимизации метрики **F1-score**.
- **Агрегация:** Вердикт выносится по скользящему среднему (например, если N из последних M чанков помечены как fake).

### Метрики оценки и бизнес-фокус
В реальных звонках доля дипфейков крайне мала, поэтому ROC-AUC или Accuracy дадут завышенную, оптимистичную оценку. 
Для связи с бизнес-ценностью (где цена пропуска дипфейка катастрофична) фокус ставится на Recall, а балансирующей оценкой выступает **F1-score**.

| Метрика | Назначение | Приоритет |
|---------|------------|:---------:|
| **F1-score** | Основная метрика. Оценивает реальную способность находить дипфейки без искажений из-за дисбаланса классов | 🥇 **Основная** |
| **EER (Equal Error Rate)** | Для сравнения с академическими SOTA-бенчмарками | 🥈 Вспомогательная |
| **Latency инференса** | Скорость ответа модели (важно для real-time детекции) | 🥉 Контрольная |

### Критерии успешности
| Уровень | F1-score | EER | Latency (на чанк) |
|---------|:--------:|:---:|:-----------------:|
| **Минимальный** | ≥ 0.85 | ≤ 15% | < 2 сек |
| **Оптимальный** | ≥ 0.90 | ≤ 8% | < 1 сек |
| **Отличный**    | ≥ 0.95 | ≤ 3%  | < 500 мс |
